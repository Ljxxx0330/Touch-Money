# TouchMoney · 触钱

> 一个给大学生用的**消费感知与资金管理**网页应用：把生活费装进一个看得见、摸得着的虚拟钱包里，
> 花出去的钱会从钱包里真实地抽出钞票、找回零钱，余额随之平滑变化。
>
> **这是一个个人开发的消费感知工具原型，不是银行软件，也不是支付软件。**
> 它不连接任何支付系统，不替你做决定，也不评判你的消费。

- 口号：**让每一笔消费，都被真正感受到。**
- 理念：**让数字重新拥有重量。**
- 当前版本：v1.3.0（数据格式 v1，无需迁移；v1.3.0 把界面改成了手机页形态）
- 所有数据只存在你自己浏览器的 LocalStorage 里，默认不上传。

---

## 1. 背景

很多记账工具把消费变成一串越滚越小的数字：本月支出 860.00、余额 1140.00。
数字是对的，但人对「一千多块钱」和「一百多块钱」的感觉，并不会因为小数点挪了一位而改变。

TouchMoney 的出发点是反过来：**把钱还原成可以数的东西**。
钱包里的钞票按真实人民币面额（100 / 50 / 20 / 10 / 5 / 1 元，加上角、分硬币）以最少张数摆放，
花掉 20 元时你会看见一张 50 元被抽走、找回 20 元和 10 元，钱包里的张数与构成随之改写。
「钱变少了」这件事因此变成一件看得见的、有过程的事，而不是一行统计数字。

它服务的场景很具体：每月拿到一笔生活费，想知道还剩多少、花到哪去了、想买的东西是否真的需要，
但又不想被记账 App 追着打卡、不想被「你已经超支了」这种话教训一顿。

## 2. 理念与边界

TouchMoney 明确**不做**下面这些事：

- **不羞辱用户**：不用红色大字警告、不用「你又乱花了」这类措辞。
- **不制造焦虑**：余额不足时只做温和提示，绝不阻止你记录一笔真实发生的消费。
- **不阻止必要消费**：它不替你决定「这笔该不该花」，只把结果摆在你面前。
- **不替用户做决定**：确认页给足信息（消费前后余额、本月已消费、剩余预算、占初始生活费比例），按下去的是你。

## 3. 核心功能

底部五个标签，加两个从标签页里进入的子页，一共七个页面，每个都是真入口、都能真做事：

| 页面 | 在哪 | 里面有什么 |
| --- | --- | --- |
| 我的钱包 | 标签 1 | 本月初始生活费与「调整」入口、本月已消费与本月剩余预算、虚拟钱包（显示当前余额的最少张数构成）、当前可支配余额、本月预算使用进度、今日支出、最近五笔、愿望清单前三条 |
| 记一笔 | 首页大按钮进入，返回箭头回钱包 | 金额、分类（七项）、这笔钱花在哪、日期、备注、是否必需开关；边填边显示「这笔钱记进去之后会发生什么」 |
| 消费记录 | 标签 2 | 分类药丸横向滑动筛选；搜索、排序、日期区间收在标题栏的搜索图标里；按天分组、每天一个合计；点一行看详情，可以改可以删 |
| 消费统计 | 标签 3 | 日 / 周 / 月 / 年切换、支出大数字与日均、分类环形图与图例、近七天折线图、预算与剩余、区间笔数与平均每笔 |
| 愿望清单 | 标签 4 | 想买 / 暂不购买 / 已购买 / 冷静期筛选、每条的预计价格与冷静期状态、标记已购买、记实际消费、编辑与删除 |
| 我的 | 标签 5 | 头像行（点整行回钱包）、生活费设置、预算提醒、数据导出、数据导入、载入示例数据、清空所有数据、关于 |
| 生活费管理 | 从「我的」进入 | 本月初始生活费与实时预览、周期起始日、结转开关、提醒阈值、往期各期表格 |

三件贯穿全站的事：金额一律以「分」为单位存储、展示时才转成元；「初始生活费 / 当前可支配余额 / 本月累计消费 / 本月剩余预算」这四个数字永远分开写，不互相冒充；任何会改数据的操作都先给你看清会发生什么，再动手。

## 4. 技术栈与选择理由

**原生 HTML5 + CSS3 + JavaScript（ES Modules）+ LocalStorage + 原创 SVG/CSS 动画。**
没有框架、没有第三方依赖、没有构建步骤、没有外部字体与图片。

选择理由：需求本身是「单页 + 本地存储 + 第一版不需要后端 / 数据库 / 支付 / AI」，
框架在这里只会带来构建链和依赖成本，换不回任何功能收益。
钱包与纸币的视觉全部用 CSS 渐变、纹理、阴影与 SVG 手工搭出来，反而比引图库更贴合需求。

代价只有一个：ES Modules 在 `file://` 下会被浏览器按 CORS 拦掉，所以**直接双击 index.html 打不开**。
项目自带一个零依赖的静态服务器（`tools/serve.cjs`），一条命令就能跑起来，见下一节。

## 5. 本地运行

需要 Node.js（本机在 v24.20.0 上开发验证；能跑 `node` 的任意较新版本都可以）。

```powershell
cd E:\TouchMoney
node tools/serve.cjs
```

然后浏览器打开 **http://127.0.0.1:4173/** 。换端口：

```powershell
$env:PORT=8080; node tools/serve.cjs
```

第一次打开时还没有生活费设置，页面会显示初始化引导（不会凭空编一个余额给你）。
想直接看效果，点引导里的「载入示例数据看看效果」，或去「设置 → 载入示例数据」。
示例数据是 10 笔消费 + 2 条愿望 + 2000 元生活费，随时可以在设置里清空。

跑测试（同样在项目根目录）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run-tests.ps1
```

完整输出写在 `tools/test-output.txt`。

## 7. 数据逻辑

**存储位置**：浏览器 LocalStorage，键名 `touchmoney.v1`。读到的 JSON 损坏时，原文会被备份到
`touchmoney.corrupt-backup.<时间戳>` 键下，然后以空白状态安全启动，不会崩。

**消费记录字段**：`id, amount, title, category, date, note, isNonEssential, createdAt, updatedAt`
**愿望清单字段**：`id, name, priceCents, addedAt, reason, plannedDate, status(pending|hold|purchased), coolingEnabled, purchasedAt, recordedRecordId, createdAt, updatedAt`

口径上的几条硬规则：

- **金额一律以整数分存储**，展示时才转成元；不会出现 0.1 + 0.2 = 0.30000000000000004 这类浮点尾巴。
- **日期一律按本地时区**计算与分组，不用 UTC，避免「今天」在晚上被算成明天。
- **四个数字严格分开**，不混用：
  - 本月初始生活费：这个预算周期的生活费额度；
  - 本月累计消费：只统计落在本周期内的记录；
  - 本月剩余预算：本期生活费 − 本期消费（**不会**把全部历史消费从当月扣掉）；
  - 当前可支配余额：开启结转时 = 本期剩余 + 往期结余；关闭结转时 = 本期剩余。
- **预算周期**默认每月 1 日起（自然月），可改成每月 1–28 中任意一天起，适配「生活费每月 10 号到账」这类情况。
- **跨月**：历史消费保留，新周期按设置重新计算预算；往期单独设过生活费就按往期自己的值算。
- **愿望清单不是账本**：清单里的价格只是参考，加入清单与标记已购买都不扣钱；
  只有「记实际消费」这一步才生成一条真实记录并扣款，且同一条愿望不会重复扣款。

## 8. 界面与交互设计

界面是**手机页形态**（v1.3.0 起，之前是桌面三栏，被这一版取代）：

- 窄屏（窗口 ≤760px）：手机页全出血铺满窗口，没有设备边框装饰。
- 宽屏（窗口 ≥761px）：手机页居中放进一个 430px 宽的设备框，框高 `min(880px, 可用高度)`，带圆角、边框与投影；窗口 ≥1000px 时左侧另有一栏产品介绍与卖点卡，设备框在右栏。设备框**永远完整可见、整页不需要滚动**——实测 1440×900、1366×768、1280×800、1100×900、1024×768、1000×700、1000×620、1200×700 八档：设备框完整可见、标签栏可见、文档不滚动、横向溢出 0。
- 滚动只发生在手机页内部（`.phone-screen`），标题栏与标签栏钉在设备框上；模态框、消费覆盖层、轻提示都挂在设备框内部，只盖住手机页，不会盖到浏览器窗口边缘。
- 确认与消费成功是**整屏**的，不是浮层小卡片：按钮钉在底部，内容区自己滚动，320px 宽的手机上也不会溢出、也不会把按钮挤出屏幕。
- 配色：主背景 `#F8F5EF`、卡片 `#FFFCF7`、品牌深绿 `#214E35`、辅助绿 `#477B50`、浅绿 `#DCE9D8`、纸币红 `#D96B5D`、纸币绿 `#80A98B`、纸币蓝绿 `#79AEB5`、暖金 `#D7AE65`、主文字 `#252B26`、辅助文字 `#85877F`、分割线 `#E9E3D9`。
- 字体是系统字体栈，不加载任何外部字体；图标全部是内联 SVG（30 个）；页面里没有 emoji、没有外链图片。第三方脚本只有一个：**内置**的 GSAP 3.13.0（`js/vendor/gsap.min.js`，随仓库一起分发，不走 CDN、不发网络请求），只用于钱包现金动画，摘掉它应用照常能用（见第 9 节）。
- 皮革钱包与纸币是**原创 SVG/CSS 抽象视觉**，不是人民币照片：《人民币图样使用管理办法》对图样使用有限制，票面人物肖像也不便处理，所以走「具有人民币色彩与纸张质感的抽象纸币」这条路，并在界面上写明「纸币是虚拟视觉表现，不代表真实货币」。
- 钞票按**面额分组**：下边对齐、向右等距排开，一组一色（¥100 红、¥50 绿、¥20 黄、¥10 蓝绿、¥5 紫、¥1 橄榄绿），组内一张压一张往左上叠成阶梯、只压住前一张的左下角。硬币贴在钱包**左缘外侧**、下缘与钞票对齐、一枚压一枚往右上叠（金属扣带在右边，右边没有地方放）。
- **收起时这一沓整体压进袋口**（整层往下 14%）：实测钞票上缘在钱包盒 46% 处、前盖上沿 52%，所以每一组只露出上缘那一条约 6%（390×844 下约 14.5px、1440×900 下约 15.9px、320×700 下约 11.1px），面额数字藏在袋口里——这就是你要的「初始状态下钞票在这个偏下的位置」。这条压低由 GSAP 驱动（见第 9 节）；GSAP 缺席时由 CSS 兜底规则完成同一件事。
- **鼠标放在钱包上时这一整层抬回原位**（压低归 0），同时每一组各自向上摊开（间距按比例放大、组内最下面那张不动）：这时才是完整的钞票脸与面额数字，沓顶升到 16%。张数徽标同时淡出，否则会被升上来的钞票压住半截。这条展开由 GSAP 驱动（见第 9 节）；GSAP 缺席时退回 CSS 过渡，展开量一样，只是没有整层回落的补间。
- 张数多时 JS 会自动收紧间距、展开幅度也跟着缩，所以最多 12 张钞票 + 4 枚硬币也不会糊成一团、也不会溢出卡片。只有触摸、又没有 GSAP 的设备才不压低——没有悬停可用，压着就永远看不见钞票；GSAP 在位时触摸设备照样压低、照样能点开展开。票面上不再印「虚拟」二字——卡片下方本来就写着「纸币是虚拟视觉表现，不代表真实货币」。

- 有交易上下文的那只钱包（确认框、消费覆盖层）里，**鼠标悬停时只有参与这笔的钞票与硬币会抬起来展开**，没参与的一张都不动：钱包知道这笔要抽出哪几种面额、各几张（`js/ui/wallet.js` 的 `involvedMap` 与 `setTransaction`，传的是**金额**，内部用 `spendBills` 按这笔钱自己的最少张数拆法算），堆里恰好给那几张挂上 `is-involved` 并按「参与那几张里的第几张」重新编号；悬停时只有它们抬起来继续往上摊、临时提到前盖之上一点好让数字露全，没参与的那几张实测停在袋口里一动不动。
- 确认框里这一点最直观：框里的钱包已经知道这笔要动哪几张，所以你在确认框上悬停看到的展开，就是确认之后覆盖层里真正会飞的那几张。
- 支持系统的「减少动态效果」：开启后钱包不压不抬、覆盖层直接进结果态、数字与张数立刻到位，数据与流程完全不受影响。

## 9. 现金动画（花了多少就抽出多少）

钱包里显示的永远是当前余额的**最少张数**构成（`js/core/notes.js` 贪心求最少张数；面额 100 / 50 / 20 / 10 / 5 / 1 元与 5 角 / 1 角 / 1 分，单位是分）。三个地方会播动画：

1. **记一笔**——确认之后；
2. **调整本月初始生活费**——调高是钞票逐张落进钱包，调低是逐张抽出；
3. **愿望清单的「记实际消费」**——标记已购买之后从清单里记这笔真实花费。

**花费的口径（第六轮改过）：一笔花多少，就按这笔钱自己的最少张数拆法去抽。** 花 124.00 元，抽出的就是 ¥100 + ¥20 + ¥1 + ¥1 + ¥1 共 124.00 元——向上展开的是这几张，飞出去的也是这几张，钱包里其余面额一张都不动。

这一版之前演的是另一套口径：按钱包新旧构成的**真差**播放，抽出多少、找回多少，两头相减才是这笔（当时还举过「同一余额花 99.99 元，抽出 ¥100 一张、找回 1 分」这种数学上没错但看着有点怪的例子）。第六轮按你的要求改成「花了多少就抽多少」，**不再看新旧构成差、也不再演找回**。

覆盖层时间线：要花的钞票从**它们在钱包里的真实位置**起飞（堆位规划与飞行落点共用同一份计算，动画结束时钞票不会「跳」一格归位），向上飘出、逐张淡出（逐张错峰 48ms、单张 460ms）→ 余额数字平滑滚动到新值 → 结果态（这次动了多少钱、余额变成多少）→ 自动关闭；中途可以按「跳过动画」直接到结果态。存入是新钞票从钱包上方落进各自槽位。数字滚动带墙上时间看门狗：浏览器把页面切到后台、`requestAnimationFrame` 长时间不给帧时，最迟在计划时长 +120ms 内落到最终值，不会停在半路。动画整体失败也不影响数据——数据在动画之前就已经写进 LocalStorage 了。覆盖层里钱包下方那行「钱包里：…」是读屏专用（视觉上没有，读屏仍能听到）。

**动画引擎与降级**：现金动画由内置的 GSAP 3.13.0 驱动（`js/vendor/gsap.min.js`，许可见第 16 节与 `js/vendor/GSAP-NOTICE.txt`）。`js/vendor/gsap-boot.js` 在 GSAP 加载成功时给 `<html>` 挂上 `gsap-on` 类，CSS 里那些「压低 / 悬停展开 / 飞行」的兜底规则全部写成 `html:not(.gsap-on)` 前缀，所以 GSAP 在位时它们一条都不生效、不会与 GSAP 抢同一个属性。GSAP 缺席（文件被删、被拦、`<script>` 没跑）时自动降级到 CSS 关键帧，压低与悬停展开照旧，只是没有逐张错峰。开启系统「减少动态效果」时覆盖层直接进结果态，数字与张数立刻到位。

## 13. 隐私说明

1. 所有数据只存在**这台设备的这个浏览器**里（LocalStorage 键 `touchmoney.v1`），没有账号、没有服务器、没有网络请求。
2. **不收集**支付密码、银行卡密码、微信支付凭证，也不连接任何支付系统。
3. 金额以整数分保存，日期按本地时区保存；导出的是纯文本 JSON，你能直接读、直接改。
4. 导入时会校验文件结构与数据类型，读不懂的字段会被丢弃并给出清洗提示，不会静默改写你的数据。
5. 清空数据有两次确认；建议清空前先导出备份。
6. 钱包里的纸币是虚拟视觉表现，**不代表真实货币**，也不代表你在银行的实际余额。

## 14. 版本限制（v1.3.0）

- 没有后端、没有数据库、没有多设备同步：换一台电脑或清掉浏览器数据，就只剩你自己导出的那份 JSON。
- 记录只有「日期」与「录入时间」，**没有交易时刻**。设计稿里的 14:23 需要新增字段并把数据格式升到 v2，这一版没加，界面上也就不假装它存在。
- 分类固定七项（餐饮 / 交通 / 学习 / 购物 / 娱乐 / 日用品 / 其他），不能自定义、不能拆类。
- 纸币与皮革钱包是抽象视觉，不代表真实货币，也不追求人民币图样的精确还原。
- 界面层没有自动化测试；动画 GIF 未录。
- 钱包里最多**绘制** 12 张钞票 + 4 枚硬币（每种面额最多 6 张）：余额张数再多也只画到这个上限，张数徽标写的是真实总张数。这是为了在小屏上还能看清每一组，不是数据口径。
