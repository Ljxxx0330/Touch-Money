# TouchMoney · 触钱

> 让每一笔消费，都被真正感受到。

一个给大学生用的**消费感知与资金管理**网页原型。它不是银行 App，也不是记账工具的简化版——它关心的是「这笔钱花出去之后，你的钱包变成了什么样子」。

**这是个人开发的消费感知工具原型，不是银行软件，也不是支付软件。** 它不连接微信支付 / 支付宝 / 银行卡，不采集任何支付凭证，也不替你做消费决定。

---

## 1. 项目背景

很多大学生第一次独立管理生活费。记账 App 能给出一堆图表和百分比，但「本月支出 ¥1,382.50」这个数字对很多人来说是抽象的——钱在屏幕里只是一个不断变小的数字，花掉的时候没有任何感觉。

TouchMoney 想解决的就是这个「没有感觉」的问题：把虚拟的钱重新做成一叠可以打开、会减少的纸币，让记账这个动作在屏幕上留下一次可见的物理过程。

## 2. 设计理念

- **让数字重新拥有重量。** 记一笔消费之后，你会看到钱包被打开、纸币被拿走、余额滚动到新数字——而不是只看到一行 toast。
- **先看清，再确认。** 每一笔消费在写进账本之前，都会先展示「消费前余额 → 消费后余额」「本月已消费」「本月剩余预算」「本笔占本月初始生活费的比例」，你确认了才落库。
- **不羞辱、不制造焦虑、不阻止必要消费。** 余额不足时它只会温和提示「余额会不足，但这笔消费是真实发生的，触钱不会阻止你记录它」，永远不会拦住你记录真实发生的事。
- **帮你理解，不替你做决定。** 它不评判「奶茶不该喝」，也不自动生成预算建议；它只把资金变化如实摆出来。
- **动画只是感知层。** 动画失败或被跳过时，数据一样正确更新（代码里动画全程被包在可降级的执行里）。系统开启「减少动态效果」时会自动改用无动画的结果展示。

## 3. 核心功能

| 模块 | 说明 |
| --- | --- |
| 我的钱包（首页） | 虚拟钱包是视觉中心：余额、纸币面额构成、本月初始生活费 / 本月已消费 / 本月剩余预算、预算使用比例、今日消费、最近消费、愿望清单摘要、快捷记账。**首次打开且未设置生活费时显示初始化引导，不会显示任何猜测出来的"余额"。** |
| 记一笔 | 金额 / 名称 / 分类 / 日期 / 备注 / 「非必需」标记；金额必须大于 0；提交前实时预览消费后余额；防重复提交。 |
| 消费感知确认 | 确认页展示消费名称、金额、消费前余额、消费后余额、本月已消费、消费后剩余预算、本笔占初始生活费比例；只有点「确认并记录」才写数据，「返回修改」不改任何东西。 |
| 虚拟现金动画 | 钱包打开 → 纸币元素变化 → 余额平滑滚动 → 展示本次消费与新余额；可跳过；动画不影响记账结果。 |
| 生活费管理 | 每月初始生活费、预算周期起始日（1..28 日）、可选结余结转、预算提醒阈值；明确区分**初始生活费 / 当前可支配余额 / 本月累计消费 / 本月剩余预算**四个数字；改生活费前先预览余额变化并二次确认，历史消费记录一条不少。 |
| 愿望清单 | 名称 / 预计价格 / 加入日期 / 购买原因 / 计划购买日期；新增、编辑、删除、标记已购买、暂不购买；可选 24 小时冷静期（必须自己勾选，默认关闭）。**标记已购买本身不扣钱**，只有「记实际消费」才真的记账，且不会重复扣款。 |
| 消费统计 | 今日 / 本周 / 本月、分类占比、最近七天趋势、预算使用比例；全部来自真实本地记录，无数据时给空状态而不是 0 元假数据；日期按本地时区计算。 |
| 消费记录 | 按日期分组、按分类筛选、按名称/备注搜索、查看详情、编辑、删除（二次确认）；编辑与删除后余额与统计同步重算。 |
| 设置 | 生活费与预算入口、本地存储占用、导出 JSON、导入（合并 / 替换 + 导入前预检）、清空（两次确认）、示例数据、关于与隐私说明。 |

## 4. 技术栈与选择理由

**原生 HTML5 + CSS3 + JavaScript（ES Modules）+ LocalStorage + 原创 SVG / CSS 动画。没有框架、没有第三方依赖、不需要构建步骤。**

理由：需求本身是一个「单页 + 本地存储 + 无后端」的应用，数据量小、交互集中在一台设备上。引入 React / Vue 只会带来构建工具链和依赖维护成本，对这个体量的项目没有收益；而需求明确要求「不引入复杂框架」「不为视觉引入复杂依赖」。所以选择浏览器原生能力 + ES Modules 模块化，代码直接可读、可直接运行。

代价是：ES Modules 在 `file://` 协议下会被浏览器的 CORS 规则拦住，因此**必须通过本地静态服务器打开**（见下一节，仓库里自带一个零依赖的服务器脚本）。

- 金额一律以**整数分**存储，展示时才转成元，避免 `0.1 + 0.2` 这类浮点误差污染账本。
- 日期全部按**本地时区**计算（`dates.js` 自己实现日期键与周期计算），不使用 UTC，避免跨日/跨月统计偏差。
- 图标与钱包、纸币图形全部是手写 SVG / CSS，没有图片资源、没有付费字体、没有 emoji 图标。

## 5. 本地运行

需要 Node.js（用于跑测试和起本地服务器；应用本身只需要一个现代浏览器）。

```bash
# 在项目根目录执行
node tools/serve.cjs
# 然后浏览器打开  http://127.0.0.1:4173/
```

- 直接双击 `index.html`（`file://`）时模块加载会被 CORS 拦住，页面会提示「需要模块服务器」，这是预期行为。
- 换端口：`PORT=8080 node tools/serve.cjs`（PowerShell：`$env:PORT=8080; node tools/serve.cjs`）。
- 也可以用任何静态服务器（`python -m http.server`、`npx serve` 等）打开项目根目录。
- 首次打开是空白引导页；想立刻看到效果，点引导页上的「载入示例数据看看效果」（写入的是明显的演示数据，随时可在设置里清空）。

## 7. 数据逻辑

- 消费记录字段：`id, amount, title, category, date, note, isNonEssential, createdAt, updatedAt`（`amount` 为整数分）。
- 愿望条目字段：`id, name, priceCents, addedAt, reason, plannedDate, status(pending|hold|purchased), coolingEnabled, purchasedAt, recordedRecordId, createdAt, updatedAt`。
- 存储键：`touchmoney.v1`；导出信封：`{ app, appLabel, exportedAt, schemaVersion, data }`。
- **四个数字口径严格分开**：本月初始生活费 / 当前可支配余额 / 本月累计消费 / 本月剩余预算。往期消费不会从本期预算里扣，只在开启结转时作为「上一期结转」滚入本期余额。
- 预算周期起始日可设为每月 1..28 日；跨月保留全部历史，新周期按当期设定计算。
- LocalStorage 读失败或 JSON 损坏：把原始内容备份到 `touchmoney.corrupt-backup.*`，按空白状态安全启动，不崩溃。

## 9. 已在浏览器中验证的内容（v1.0.0）

以下是在 Chrome（Playwright，390×844 手机视口）+ 本地服务器上实际点出来的，不是"应该可以"：

- 空数据首屏显示初始化引导，不显示猜测余额；设置生活费 / 载入示例数据后进入钱包视图。
- 记一笔 → 消费感知确认 → 现金动画 → 钱包余额与统计同步；「返回修改」与 ESC 取消都不改数据。
- 现金动画实际时序：纸币飞走 → 旧纸币淡出 → 按新余额重算面额 → 余额滚动 → 自动关闭；「跳过动画」与「完成」可提前结束。
- 统计视图：今日 / 本周 / 本月、非必需占比、分类占比、七天趋势，数字与记录逐笔核对一致。
- 记录视图：详情、编辑、删除（二次确认）、分类筛选、关键词搜索、无结果空状态。
- 愿望清单：标记已购买不扣款；「记实际消费」按真实金额扣款；重复调用不会二次扣款；删除该笔记录后可重新记账。
- 生活费视图：改生活费（预览 + 确认，历史记录保留）、改周期起始日（跨周期重算）、结转开关、各周期明细表。
- 设置视图：导出 JSON 文件、导入预检（合并 / 替换）、合并导入跳过重复、替换导入完整落地、清空两次确认、坏 JSON / 别家应用文件 / 空文件的失败提示且不改动数据。
- 刷新与深链接（`#add` 等）停在原页面；数据在刷新后仍在。
- 键盘：Tab 焦点陷阱与 ESC 关闭（含堆叠模态只关最上层）、关闭后焦点归还、表单 Enter 提交、输入框聚焦后滚动到可视区。
- 系统「减少动态效果」开启时动画降级为直接展示结果；`prefers-reduced-motion` 下动画与过渡近零。
- 宽屏（≥720px）双列/三列布局、窄屏（≤420px）单列布局；无外部字体与图片请求。

开发过程中实际发现并修掉的问题（都留下了回归测试或浏览器复验）：`app.js` 的模块路径写错导致首屏 404、`add-view.js` 的 TDZ 报错、深链接回到钱包、钱包动画 `setTimeout` 笔误、百分比显示浮点尾巴、周期明细 `<table>` 未挂进 DOM、设置视图金额无千分位、替换导入丢 `settings.months`、ESC 关不掉模态（`modal.js` 读错对象属性）等。

## 11. 隐私与数据

- 所有数据只保存在**这台设备的浏览器 LocalStorage**（键名 `touchmoney.v1`），不上传、没有网络请求、没有分析脚本。
- 不采集支付密码、银行卡密码、微信支付凭证；不连接任何支付系统。
- 金额以整数分保存，日期按本地时区保存，导出文件是纯文本 JSON（内容完全可见）。
- 导入 / 导出 / 清空全部由你主动点击触发；清空有两次确认，建议先导出备份。
- 「载入示例数据」写入的是明显的演示数据（记录 id 前缀 `demo_`），不是真实财务信息；代码里没有硬编码的真实用户财务数据。
- 浏览器隐私模式或禁用本地存储时，应用会提示存储不可用，仍可浏览但无法保存。

## 12. 版本限制（v1.0.0）

- 没有后端与数据库：换浏览器、换设备、清理浏览器数据都会丢；不提供云同步与多设备。
- 不连接微信支付 / 支付宝 / 银行，不能自动导入真实账单，全部要手动记。
- 单币种（人民币元）、单笔上限 1,000,000 元。
- 预算周期只支持「每月第 N 日」一种口径，不支持按周或自定义循环。
- 没有自动预算建议、预测、AI 分析——这是刻意的，它不替你做决定。
- 界面层没有自动化测试（只有数据层 61 个单测 + 手工浏览器验证）。
- 未做 PWA / 离线缓存 / 桌面端安装；宽屏是响应式适配而非独立桌面形态。
- 现金动画只有静态截图，没有录屏 GIF。
